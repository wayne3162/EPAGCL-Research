# EPAGCL: test real node-classification predictions

This demonstration evaluates a **trained** official EPAGCL encoder checkpoint and prints per-node predictions from a newly trained linear classifier. It does **not** retrain the encoder, and it does not claim to reproduce the paper's exact five-run result.

## 1. What is tested?

- Load the original dataset using the official `Load_data.get_dataset` function.
- Load official EPAGCL `MyModel` weights from a `.pth` file.
- Pass the **original graph** (not either augmented view) through the frozen encoder to obtain its node embeddings.
- Randomly split node IDs into 10% training / 10% validation / 80% testing, using an explicit seed.
- Train a multinomial logistic-regression (`torch.nn.Linear` + CrossEntropy) classifier on training embeddings and **training labels only**.
- Use validation accuracy to choose a classifier checkpoint; examine the test set once at the end.
- Save each test node's true label, predicted label, whether the prediction was correct, and softmax confidence.

The graph is transductive: all nodes can be included in the original graph used to learn embeddings; this is **not** the same as exposing test labels to the classifier.

## 2. Usage (in an existing EPAGCL environment)

Copy `epagcl_predict_nodes.py` into the root of the official repository next to `main.py`, `Model.py`, and `Load_data.py`.

```bash
python epagcl_predict_nodes.py \
    --dataset Cora \
    --data-root ../datasets \
    --checkpoint 'trained_models/Cora/completed_YOUR_RUN/1/ckpt_epoch500.pth' \
    --seed 42 \
    --eval-epochs 3000 \
    --compare-raw
```

Replace the quoted checkpoint path with the **real** file path generated by your training run. If you trained an encoder using different dimension settings, specify matching `--feat-dim` and `--proj-hidden-dim` values.

The output directory `node_prediction_results/` contains:

- `test_predictions.csv`: one row per test node; open it to show your instructor actual successes and failures.
- `summary.json`: test accuracy, selected validation epoch, data sizes, class confusion matrix, and optional raw-feature baseline.

## 3. What the checkpoint is

The official training code saves `ckpt_epoch{epoch}.pth` at intervals and `best_ac_ckpt.pth` after some evaluations. `ckpt_epoch500.pth` means an **encoder** snapshot at epoch 500, not a trained classifier.

For cleaner evaluation, prefer a **fixed-epoch** encoder checkpoint rather than one selected based on its test accuracy. The public `main.py` saves its "best accuracy" checkpoint using evaluation accuracy, which can make that selection biased.

## 4. Two public-repository issues to check before training

The GitHub repository code visible on November 22, 2026 contains apparent issues in these two files:

**Arguments.py**: code later accesses `args.not_drop_feature_random`, but the argument is not defined. Add this line with the other `parser.add_argument(...)` flags:

```python
parser.add_argument('--not_drop_feature_random', action='store_true')
```

**main.py**: `train()` returns only `best_ac` but later `ac, z = train(...)` tries to unpack two values. Change it to:

```python
ac = train(data, adding_edge_weights, adding_edge, dropping_edge_weights, args)
```

These are **source-code observations**, not proof that all public versions will fail in the same way. Check the version you actually downloaded before changing anything.

## 5. Limitations and verification

- The script was syntax-checked and smoke-tested locally against a **synthetic fixture** matching the official `MyModel` and `get_dataset` interfaces. It has **not** run against the actual Cora dataset or a real EPAGCL checkpoint in this environment, so there are no genuine test-accuracy results in this package.
- It follows the paper's 10/10/80 linear-evaluation idea but uses validation-only model selection. Its random split and classifier initialization can differ from the official implementation, so do not expect the Table 2 accuracy to match exactly.
- Integer class IDs correspond to the dataset's label coding. They are not themselves a human-readable research-topic name.
- The `--compare-raw` switch is a useful sanity check, but it is not a substitute for comparisons with other graph-contrastive methods such as GCA.
